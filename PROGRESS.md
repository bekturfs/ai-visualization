## Правила, которые нельзя нарушать

1. `npm run build` (`tsc -b && vite build`) проходит чисто **до** каждого коммита.
   `noUnusedLocals` / `noUnusedParameters` включены — неиспользованный параметр ломает сборку.
2. Никаких ассетов: ни картинок, ни звуковых файлов, ни моделей, ни шрифтов. Текстуры
   рисуются в canvas, звук синтезируется.
3. Зависимости добавляем осознанно и по делу. Разрешённый список — тот, что в
   `package.json`; каждая новая должна оправдать свой вес в сборке.
4. Модули игры импортируют только из `types.ts` / `config.ts` / `rng.ts` / `road.ts` /
   `num.ts` / `ctx.ts`. Стыкуются они только в `src/main.ts`.
5. Пуш только в `claude/instagram-reel-review-plcthz`, через `git push -u origin <branch>`.

## Версия 2 — без React, с настоящим 3D-стеком

По прямому решению владельца: React убирается, вместо него подключены
`postprocessing`, `meshline`, `lil-gui`, `stats.js` и `@dimforge/rapier3d-compat`.
Правило «никаких новых зависимостей» этим отменено — но правило «никаких
ассетов» остаётся в силе.

Порядок важен: сначала уходит React (он трогает все те же файлы), потом слой
эффектов, потом инструменты, и только в конце физика — она меняет ощущение игры,
и её нужно настраивать на уже стабильной картинке.

- [x] A. Контракт `src/game/ctx.ts` (`System` / `Overlay`)
- [x] B. Порт сцены: `scene/*.tsx` → `systems/*.ts`, оверлеи → обычный DOM/SVG.
      Заодно `effects` переезжает на `postprocessing`, следы встречных — на `meshline`
- [x] C. `src/main.ts`: рендерер, цикл, ресайз, сборка систем; React выкинут из
      `package.json`
- [ ] D. Физика на rapier: твёрдое тело в локальной системе координат
- [x] E. Панель `lil-gui` + `stats.js`, только в dev
- [ ] F. Эффекты: god rays, частицы, отражения на мокром асфальте, смаз на скорости

### Что нельзя потерять при переписывании

Это те свойства, ради которых игра вообще работает. Они не зависят от React и
должны пережить порт:

1. Всё состояние — один мутируемый `Game`, он не в реактивном хранилище.
2. Камера стоит в нуле, мир едет мимо: в координаты вершин не попадает
   абсолютная дистанция.
3. Декорации — чистая функция от хеша ячейки, ничего не хранится.
4. Симуляция идёт фиксированным шагом 1/120 и не зависит от частоты кадров;
   `npm run soak` это проверяет и должен продолжать проходить.
5. Модули не импортируют друг друга — только `types` / `config` / `road` / `rng` /
   `num` / `ctx`. Сходятся они в `main.ts`.

## Что осталось честно недоделанным

Ничего из этого не мешает играть, но знать надо:

1. **Производительность на настоящей видеокарте не проверена.** В контейнере нет
   GPU, всё рисует SwiftShader: 3 fps на качестве 2 и 2 fps на мобильном
   портрете. Это ничего не говорит о реальном железе, но и не подтверждает, что
   там всё хорошо. Первое, что стоит сделать на машине с GPU, — открыть игру и
   посмотреть частоту кадров на всех трёх пресетах.
2. **Звук ни разу не был услышан.** В headless нет звукового устройства. Код
   синтеза компилируется, не падает и не сыплет ошибок в консоль, но что он
   звучит как задумано — непроверенное утверждение.
3. **Яркость и «шум» правились по отзыву с настоящего экрана, вслепую.** В
   SwiftShader кадр выглядит иначе, чем на живой видеокарте, поэтому значения
   после этой правки — предположение, проверенное только по скриншотам. Если
   станет наоборот тускло, крутить в обратную сторону: яркости разметки в
   `Road.tsx`, `GLOW_GAIN`/`POOL_GAIN`/`TOWN_GAIN` в `Lights.tsx`, `uTwinkle`
   в `Sky.tsx`, `bloomStrength` в `config.ts`.

Закрыто с прошлого раза: главы неба проверены по-настоящему (`npm run soak`
показывает 0 → 1 → … → 11 за 65 км), физика больше не зависит от частоты кадров,
мёртвый `COLORS.trunk` убран.

  результат (0.00 м на 15.5 км). Оставшиеся 1.46 % с автопилотом — это частота
  опроса ввода, она равна частоте кадров в любой игре.
- Тот же прогон подтвердил то, что раньше было непроверенным: главы неба идут
  подряд 0 → 1 → … → 11 за 65 км, час езды (195 км) не рождает ни одного NaN,

- `npm run single` собирает всю игру в один HTML (1.3 МБ). Проверено с `file://`:
  заезд идёт, внешних запросов ровно ноль.
- Отзыв с настоящего экрана: «линии и свет горят слишком ярко и много шума».
  Разобрано на три отдельные причины.
  **Яркость линий:** у разметки дальний конец был ярче ближнего (1.35 против 1
  у осевой) — чем мельче линия, тем сильнее светила, отсюда пересвет и каша у
  горизонта. Теперь дальний конец приглушён.
  **Яркость огней:** `GLOW_GAIN` 2, `POOL_GAIN` 1.3, `TOWN_GAIN` 1.55 уходили
  далеко за единицу и целиком попадали в bloom — срезаны примерно вдвое.
  **Шум:** в цепочке постобработки не было сглаживания вообще. У холста
  `antialias: false` (и это правильно — MSAA холста не доходит до таргетов
  композера), а сцена почти вся состоит из тонких ярких линий на чёрном, края
  которых в движении кипят. Добавлен `SMAAPass` — тоже штатный в three, без
  новых зависимостей, освобождает себя сам. Взят SMAA, а не FXAA: FXAA размыл бы
  мелкие яркие точки, а из них состоит всё небо. Плюс мерцание звёзд убрано с
  амплитуды 1 до 0.38 — две тысячи точек, дышащих вразнобой, читались как шум.
  Проверено: официальный прогон чистый, четыре переключения качества туда-обратно
  не роняют контекст и не сыплют ошибок.
